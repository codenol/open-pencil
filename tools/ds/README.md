# Инструменты работы с дизайн-системой

Скрипты анализа и выгрузки ДС. Работают с тяжёлыми `.fig`-файлами, которые
лежат только на сервере (`data/`, в git не хранятся).

## Выгрузка компонентов (основной сценарий)

Режет крупный `.fig` на части по компонентам: каждая часть открывается
в редакторе, привязки к токенам сохраняются.

```bash
bun tools/ds/export-components.mjs [макс_нод] [исходный.fig] [папка_вывода] [префикс]
```

Пример:

```bash
bun tools/ds/export-components.mjs 2400 data/ds-unpacked/canvas.fig data/ds-components components
```

Что делает:
- собирает компоненты и сеты со **всех** страниц, включая служебную
  (у Figma часть компонентов лежит в служебном хранилище)
- не берёт копии чужих библиотек (они линкуются отдельно)
- тянет переменные, коллекции и алиасы, на которые ссылаются компоненты
- режет на части по `макс_нод`, чтобы каждая открывалась в браузере
- пишет `manifest.json` с составом

## Остальные скрипты

| Скрипт | Назначение |
|---|---|
| `build-structure2.mjs` | реестр сущностей ДС (`ds-structure.json`) |
| `import-tokens.mjs` | импорт токенов DTCG в редактор |
| `build-relink-map.mjs` | карта соответствий копий и оригиналов |
| `analyze-ds.mjs` | что из чего состоит |
| `inspect-*.py/mjs` | разбор внутренних сущностей |

## Важно

- Из Figma в Figma не пишем: сырьё для обратного экспорта (`rawNodeFields`) выпилено.
- Рабочие страницы (витрины) не выгружаем — только компоненты.
- Тяжёлые данные (`.fig`, распаковки, `*.bin`) в git не попадают: они в `.gitignore`.
